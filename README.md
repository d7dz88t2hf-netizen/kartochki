# Карточки 1.1.0

Офлайн-приложение для карточек и интервального повторения. Один интерфейс, две нативные оболочки.

## Поддержка

- macOS 11.0 и новее, Intel и Apple Silicon; universal binary.
- Windows 10/11 x64. На Windows ARM — только через системную эмуляцию x64; отдельная ARM-сборка в этот выпуск не входит.
- Windows использует установленный Microsoft WebView2 Runtime. Если он недоступен, приложение пробует открыть интерфейс в Edge/Chrome или браузере по умолчанию. Наличие Runtime не гарантируется на каждой установке Windows 10.

## Запуск и перенос

Готовые программы находятся в `dist/`. Перенесите `Карточки.app` в «Программы» на Mac; на Windows распакуйте архив и запустите `Карточки.exe`.

Коллекция предыдущей версии открывается автоматически по прежнему пути:

- Mac: `~/Library/Application Support/Kartochki/kartochki.json`.
- Windows: `%APPDATA%\Kartochki\kartochki.json`.

Перед переходом сохраните копии `kartochki.json` и `kartochki.json.bak`. Приложение хранит предыдущую корректную версию рядом в `.bak`; это не заменяет внешнюю резервную копию. Кнопка внизу окна экспортирует все колоды, настройки и прогресс. Импорт копии добавляет колоды, не удаляя существующие; повторный импорт копии создаёт отдельные колоды.

При повреждении основного файла используется корректная `.bak`. При следующей записи повреждённый файл сохраняется отдельно с пометкой `corrupt`. Если обе копии некорректны, работа с коллекцией блокируется с объяснением, файлы не затираются. Для ручного восстановления: закройте приложение, скопируйте оба файла в безопасное место и замените основной файл корректной полной копией коллекции. Экспорт отдельной колоды импортируется через интерфейс и не предназначен для прямой замены файла на диске.

Если статус внизу сообщает об ошибке сохранения, повторите сохранение или экспортируйте все колоды. Второе окно с устаревшей коллекцией получает ошибку конфликта; сохраните его нужные изменения экспортом, затем закройте и откройте приложение снова.

## Структура

```
web/                 единый HTML/CSS/JS для обеих платформ
  model.js           валидация, формат коллекции, CSV
  app.js             экраны, импорт/экспорт, интервалы повторения
  desktop.js         подтверждение записи, очередь, платформенный мост
mac/
  main.swift         окно, меню, WebKit, закрытие после сохранения
  Storage.swift      безопасная запись, резервная копия и восстановление
  Собрать.command    universal macOS app
windows/
  main.go            loopback-сервер, защита API и браузерный fallback
  storage.go         валидация и атомарная запись
  window_windows.go  Win32/WebView2 через официальный загрузчик
  platform_*.go      блокировка коллекции и замена файла
  vendor/            загрузчик Microsoft и лицензия
assets.go            встраивание общей папки web в EXE
tests/              регрессионные и интеграционные проверки
tools/              проверка реальной оболочки macOS
```

## Сборка

Mac: установите Command Line Tools от Apple, затем запустите `mac/Собрать.command`. Обе архитектуры обязательны; ошибки сборки больше не скрываются. По умолчанию подпись локальная ad hoc. Для подписи разработчика задайте `SIGN_IDENTITY`; notarization выполняется отдельно с вашими учётными данными Apple.

Windows: нужен Go 1.24 или новее. Из корня проекта:

```sh
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags '-s -w -H=windowsgui' -o 'dist/Карточки.exe' ./windows
```

На Mac/Linux также можно запустить `windows/build.sh`. В PowerShell задайте `$env:GOOS="windows"`, `$env:GOARCH="amd64"`, `$env:CGO_ENABLED="0"`, затем выполните команду `go build` с теми же параметрами. Готовый `rsrc_windows_amd64.syso` содержит значок и версию 1.1.0; при изменении ресурсов пересоберите его из `windows/res/app.rc` с помощью `llvm-windres --target=pe-x86-64 --codepage=65001`.

Рабочих сторонних Go-модулей и npm-зависимостей у приложения нет. Playwright нужен только для тестирования. Загрузчик WebView2 поставляется с лицензией Microsoft.

## Проверки

```sh
node --test tests/model.test.cjs
go test -race ./...
```

Браузерные проверки: `npm install`, `npx playwright install chromium`, затем `npm run test:browser`. Можно использовать установленный Chrome, указав `CHROME` с путём к исполняемому файлу; `PLAYWRIGHT_MODULE` позволяет указать готовый модуль Playwright.

На Mac:

```sh
mkdir -p .build
xcrun swiftc mac/Storage.swift tests/StorageTests.swift -o .build/storage-tests
.build/storage-tests
bash tools/test-native-macos.sh
```

Тесты используют временные коллекции и не обращаются к пользовательским колодам.

## Ограничения выпуска

Список реально выполненных проверок и оставшихся проверок платформ — в `Проверка.md`. Приложение сохраняет данные локально без шифрования; содержимое доступно процессам с правами пользователя. Ad hoc подпись Mac и отсутствие Authenticode на EXE не дают доверенной подписи издателя. Для публичного распространения нужны сертификаты, notarization и проверка на реальных целевых системах.
